# ClimateGuard Platform

ClimateGuard is a local research prototype for viewing climate, disease surveillance and environmental indicators by district. The frontend is a plain HTML/CSS/JavaScript dashboard; the backend is a FastAPI service with a local SQLite database and a district-specific, calibrated Random Forest model.

The numeric forecast is generated by the backend model from measured weekly dengue reports and recent climate observations. Ollama is optional and only writes a short explanation of an already computed result. Recommended local model: `qwen3.5:4b` (roughly 4 GB model download; allow additional system memory). It is not used to calculate risk. You can omit Ollama entirely.

## Windows quick start

Open two PowerShell terminals. In both, change directory to this project folder, for example:

```powershell
cd "P:\Fusion hackthon\climateguard_platform"
```

### Terminal 1: backend

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Open `backend\.env` and replace `ADMIN_TOKEN` with a long private value. Keep `OLLAMA_EXPLANATIONS=false` initially. Start the API:

```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

The first run creates `backend\data\climateguard_platform.sqlite3`. Keep this terminal open. API docs are at [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs), and health is at [http://127.0.0.1:8000/api/v1/health](http://127.0.0.1:8000/api/v1/health).

If PowerShell blocks virtual-environment activation, you can skip activation and use the executable directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### Terminal 2: frontend

```powershell
cd "P:\Fusion hackthon\climateguard_platform\frontend"
py -3.11 -m http.server 5173 --bind 127.0.0.1
```

Open [http://127.0.0.1:5173](http://127.0.0.1:5173). The dashboard connects to the API at `127.0.0.1:8000` by default. Both terminals must remain running.

## First data setup

1. Click **Data setup** and enter the same private value you put in `backend\.env` as `ADMIN_TOKEN`.
2. Click **Load India ADM2 boundaries**. This downloads open district boundaries and fills the district selector/map.
3. Choose a district in **Focus area**.
4. Click **Fetch 4 years of NASA POWER**. The button loads one selected district at a time. It is safe to repeat because duplicate daily observations are ignored.
5. Upload a verified OpenDengue district crosswalk CSV with these exact headers: `adm_0_name,adm_1_name,adm_2_name,location_id`. Names must exactly match the surveillance file after case normalization; `location_id` must match an ID returned by `/api/v1/locations` (also visible in the dashboard/API). The system does not guess district name matches.
6. Click **Import OpenDengue extract** after the crosswalk is saved. It downloads the configured official extract. If that source changes or is inaccessible, use the API docs to upload the source ZIP/CSV instead.
7. Optional: click **Fetch WorldPop estimate** to request annual population estimates for 2022–2025 for the selected district. This is an on-demand operation and can take time.
8. Return to the dashboard and inspect the source registry, chart, and latest reporting dates. Only click **Train / refresh model** after sufficient valid weekly case data have loaded. The API requires at least 120 eligible weekly origins and enough examples in training/calibration/holdout blocks.

The first button calls may take a while because it is fetching and summarizing real data. The API's `/api/v1/jobs` endpoint and the dialog response show source ingestion outcomes. A dashboard with `—` or “unavailable” is expected until its source data exist; it never fills missing observations with demo values.

## Optional Ollama explanation

Install Ollama, then in a separate terminal run:

```powershell
ollama pull qwen3.5:4b
```

Set `OLLAMA_EXPLANATIONS=true` in `backend\.env`, restart the backend, and refresh the dashboard. Keep Ollama running. `/api/v1/health` reports whether the configured model is available. The model only explains supplied evidence; turning it off does not turn off the numeric forecast.

## Imported processed CSV format

The dashboard can import processed satellite, water, mobility, land-cover or measured vector observations. Required CSV headers:

```text
location_id,category,observed_on,value,unit,source
```

Optional headers: `observed_to,product,resolution,quality,metadata`. `metadata` must be a JSON object when present. Supported category values are `ndvi`, `evi`, `land_surface_temperature`, `surface_water_occurrence`, `water_level`, `mobility_index`, `vector_count`, `vector_larval_index`, and `land_cover`, plus other categories exposed in the API schema. Use source-native values and units; do not label climate-derived estimates as measured vector counts. Satellite source files need external Earthdata download and quality filtering before this import. The app does not claim a live satellite pipeline.

## Model scope and data notes

- The numeric model is a district-specific, calibrated Random Forest with chronological training/calibration/test blocks. It predicts whether one of the next four weekly reported dengue counts will exceed that district's training-window 75th percentile.
- The model is not an official outbreak alert, medical advice, or a substitute for public-health validation. Weak or insufficient source coverage leaves the score unavailable.
- NASA POWER values are gridded/reanalysis data at a district representative coordinate, not station observations or weather forecasts.
- OpenDengue source intervals, overlap flags, and unmatched/rejected rows are preserved for review. Correct district crosswalks are essential.
- MODIS vegetation/LST data require an external Earthdata export and quality screening. Mobility requires an authorized, aggregated source. Vector indicators require actual surveillance or site sensor readings. JRC Global Surface Water v1.4 ends in 2021 and therefore cannot supply the recent four-year water series.
- Data integrations run on demand. This prototype does not schedule automatic refreshes.

See [source documentation](https://power.larc.nasa.gov/docs/services/api/temporal/daily/), [OpenDengue data](https://opendengue.org/data.html), [geoBoundaries API](https://www.geoboundaries.org/api.html), [WorldPop API](https://api.worldpop.org/v2), and [Ollama Qwen3.5](https://ollama.com/library/qwen3.5).
